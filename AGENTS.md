# Orientações do projeto

- Fazer commits pequenos e incrementais por unidade lógica concluída (ex.: motor de risco, testes, endpoint, componente de interface ou documentação), sem acumular toda uma etapa grande em um único commit.
- Usar mensagens descritivas no padrão Conventional Commits: feat, fix, test, refactor, docs ou chore.
- Cada commit deve ser coerente e verificável; não criar commits vazios ou mudanças artificiais apenas para aumentar o histórico.
- Informar ao usuário os commits criados ao concluir cada entrega.
- Não reescrever commits existentes sem autorização do usuário.
- Antes de commitar, revisar o diff e executar as verificações pertinentes.
- Não incluir segredos, ambientes virtuais, dependências instaladas ou artefatos de build.
- Não fazer push para um remoto sem solicitação do usuário.
